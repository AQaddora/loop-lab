# Ventures: meet feature pool

This is the pool for the venture loop (`specs/meet.md` §3). The `ideate` workflow adds and re-scores rows, then queues the top 3 as OPEN entries in `loop/decisions.md`.
`build-next` flips statuses from the answered decisions. **Humans edit only `loop/decisions.md`, never this file.**

| Field | Values |
|---|---|
| Status | `pool` → `queued (D-xxx)` → `approved` → `built`, or `rejected`. PARKED goes back to `pool` with a cooldown of 3 ideate runs |
| Effort | S = 1 task · M = 2-3 tasks · L = more than 3 tasks or new infra |
| Oracle | `local` = provable on the pinned LiveKit dev server + Playwright · `cloud` = needs the LiveKit Cloud staging project · `+key` = also needs a human-provided third-party secret |
| Oracle assertion | what the venture's `tests/e2e/v-XX-*.spec.ts` / `tests/unit/v-XX-*.test.ts` does and expects. build-next copies it into the task's done-when notes. "A human looks at it" is never valid |
| Needs | grant changes (MEET-AC-02), new npm deps, other ventures, long-running processes. The decision text must repeat these |
| Lens | U user value · D differentiator · C cheapest on LiveKit · W wow-demo |

Already in v0 through the `VideoConference` prefab, so **do not propose these as they are**: basic chat (non-persistent, text streams topic `lk.chat`), screen share,
focus/grid layout, device menus, per-tile connection-quality bars, mute icons, speaking highlight.

API placement (livekit-client 2.24): `room.registerRpcMethod` / `room.registerTextStreamHandler`; `room.localParticipant.performRpc` / `sendText` / `publishData` / `setAttributes`.
RPC request and response payloads are each capped at 15 KiB. `setAttributes` needs `canUpdateOwnMetadata` in the grant, which v0 does not give.
